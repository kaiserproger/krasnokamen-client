# Battle equipment candidates

These are resource identifiers, not proof of a deliverable bundle. For local
native-client development, `KRASNOKAMEN_CLIENT_RESOURCE_PACKS` accepts this extracted
pack directory. The core `java-battle-functional` gate serves its ZIP through
the ordinary optional server resource-pack push with Loader on 26.1.2.
Vanilla's default policy prompts; automatic loading requires the per-server
Resource Packs preference to be Enabled. Functional loading and screenshot
review are separate checks.

The red crest of the crested helm and the red plume pixels of the Iron Plate
humanoid texture are a separate dyeable layer (`crested_helm_plume`,
`iron_plate_plume`, greyscale; the base textures keep a grey copy). Battle
staging dyes it per side: red `0xB92529` for side 1, blue `0x294DB7` for side 2.

Example for a core build containing the equippable codec, using its existing
summon equipment path:

```mcfunction
summon minecraft:zombie ~ ~ ~ {NoAI:1b,equipment:{chest:{id:'minecraft:iron_chestplate',components:{'minecraft:equippable':{slot:'chest',asset_id:'krasnokamen_battle:holy'}}},mainhand:{id:'minecraft:iron_sword',components:{'minecraft:item_model':'krasnokamen_battle:iron_longsword'}}}}
```

All items are element models (real depth), generated by `tools/battle_items_gen.py` and
previewed with `tools/item_models.py` (`items`, `hand`, `compare`: each model alone and
held by an armoured husk through the client's own attachment chain; the native replay
frame is the final check). Shields use the vanilla shield's board and handle size and
vanilla's held transforms; their item definitions switch on `minecraft:using_item` to
`<name>_blocking`, which carries vanilla's `shield_blocking` display, so a shield arm in the
BLOCK pose shows the face to the front. Weapons are authored along +Y with the grip at the
model centre; the display transform turns them (spear, halberd leaning forward, lance
couched forward-up, crossbow level with the prod across) and scales long weapons down
through the element grid. The bows and crossbows are static models: draw and loaded states
are not implemented. First-person display values derive from vanilla handheld
transforms; the battle gate captures the equipped spear/shield view, not every
item and pose.

Java element coordinates must stay within `[-16, 32]`. The generator contracts
oversized weapons uniformly about the model/grip centre `(8, 8, 8)` and applies
the reciprocal display scale, preserving their rendered dimensions, orientation
and attachment instead of clipping the lance tip or halberd blade.
`python3 -m unittest discover -s tools -p test_battle_items_gen.py` checks every
pack model's bounds, generated-file consistency and transformed weapon geometry.
The format-84 metadata declares `min_format` and `max_format` explicitly for
26.1.2; without them Java falls back after rejecting the pack metadata.
